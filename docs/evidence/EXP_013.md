# EXP-013 question policy evidence

Status: registered question answered, no code change required.

## Registered question

"Does answerability-aware questioning beat fixed, entropy-only, repeated-`other`,
and no-question controls, at identical safe slates?"

Answer: no. Repeated `other` beats every alternative arm measured. The shipped
line in `needle/agent.py` (`ask_attribute = "other" if turn < 10 else None`) is
retained on evidence rather than on convenience.

Falsification threshold registered before the run: an alternative policy must
gain at least +0.005 TechnicalScore over repeated `other` without losing HR@10 on
any scenario slice. No arm cleared it. The best alternative question policy lost
0.009151; the best arm of any kind lost 0.003577 and also changed state
admission rather than questioning.

## What the arms establish

**Questioning is the largest single lever measured in this project so far.**
Arm C removes only `ask_attribute` and costs 0.424477 TechnicalScore, 43 points
of HR@10, and 4.2 turns of MTTC. Retrieval quality is unchanged in that arm; the
loss is entirely the information the customer never discloses. Any future change
that suppresses questions, including a latency or "conversational polish"
change, must be measured against this number.

**`other` dominates by construction, and the public numbers agree.** In
`customer_reply`, `other` matches any constraint type while a named attribute
matches only its own bucket, and both return at most two undisclosed values. A
named attribute can therefore return nothing where `other` would have returned
two; it can never return more. Every rotation arm (E, F, G, H, I, J) loses.

**Answerability ordering does not rescue rotation (H, I, J).** Across the 200
public sessions all 800 constraints classify as feature 404, material 302, color
60, style 19, size 11, use_case 4. Five of the seven answerable buckets are
nearly always empty, so a rotation spends most turns on a bucket that cannot
answer. Ordering by observed frequency (I) recovers part of the loss but still
trails `other` by 0.018771, because even `feature` misses whenever the remaining
undisclosed constraint is a material.

**Stopping early is a trap (D).** Every public session carries exactly four
constraints and `other` returns two per reply, so two questions look sufficient.
They are not: on boundary sessions the first question is consumed by the
no-preference reply, and on intent_override sessions the reply to the turn-2
question is discarded because the override message replaces it. Both slices need
a third question. That is visible as override HR 1.000 to 0.867 and boundary HR
1.000 to 0.800 in arm D. The agent cannot detect either case in advance, and
asking is free because `evaluate()` scores the slate before it reads
`ask_attribute`. So the correct policy is to ask on every turn that has a reply.

**Withholding uninformative replies from the retrieval query does not help
(B, G).** The prediction under test was that "I don't have an additional
preference for other." dilutes the BM25 query once constraints are exhausted.
It does not: arm B loses 0.003577 and one session. The tokens are common enough
across the catalog that BM25 already discounts them, and the current
`NO_PREFERENCE_RE` handling in `needle/state.py` is sufficient because it
already stops those clauses from becoming negative constraints. This is a
recorded negative finding; the change was not made.

## Transfer risk to private

The rotation arms lose because of the bucket skew produced by
`classify_constraint`. Private targets are disjoint but the same classifier and
the same `intent_card` construction generate them, so the skew is expected to
hold; the conclusion should not be treated as verified there. `other` needs no
such assumption: it matches any type, so it is the arm that is robust to a skew
shift as well as the arm that wins on public. That is the reason to keep it,
independent of the public margin.

Public HR@10 for arm A is 0.995, so the question policy is saturated on public
and no further tuning is warranted against this set. The remaining EXP-013
scope is the belief-state work already carried by PRs #6, #9, and #10.

## Decision and rollback

Keep `ask_attribute = "other" if turn < 10 else None`. No code change.
`tests/test_question_policy.py` pins the behavior and records why, so the line is
not silently replaced by an attribute rotation that costs 0.02 to 0.09.
Rollback is not applicable: nothing shipped.
